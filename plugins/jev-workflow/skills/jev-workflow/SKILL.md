# Jev 工作流

在当前 Codex 会话中完成工作，保留用户上下文；不要启动另一套 Codex 或一次性 app-server 工作流。插件会在首次调用 `route_task` 时自动打开 TUI 风格独立小窗口；这是当前用户要求的可视化，不需要另运行启动脚本。

首次处理一个新任务时调用本插件的 `route_task`，传入用户任务摘要和 `inspect`（只读查看）或 `edit`（修改代码）。只发送任务描述，不发送源文件、密钥或私人材料。返回的 run_id 标识本次工作流，后续追问继续使用它，不因普通追问重新分流。

窗口启动会等待“可见且已渲染”的确认。返回 window_error 时，明确说明弹窗失败并保留具体原因；不能仅凭技能已加载或进程已创建就宣称窗口已打开。

根据真实返回的 effectiveRoute 执行：
- execute：在当前 CLI 会话使用原生文件、命令等工具完成任务。
- plan_review：先形成并核查计划，再执行；只读分析则复核报告证据。
- clarify：补问缺少的必要事实，继续使用当前对话，收到答案后再分流。

调用 `record_stage` 更新有实质进展的阶段：plan、work、tests、review、done。每个实际执行阶段开始时记录 running，结束时记录 completed、blocked 或 skipped，小窗口据此实时更新。它记录的是本会话报告的状态，不是独立验收器。summary 和 evidence 只包含实际工具结果支持的事实。只读任务将 tests 标记 skipped，不能声称测试通过；修改任务按项目实际测试方式验证，测试失败或缺少必要证据时标记 blocked。

可按任务需要使用当前 CLI 已有的原生子代理能力。只有真正创建了审查线程，才称其为独立审查；没有调用指定模型就不要显示 Astra/Sol 已执行。权限和审批交给当前 CLI，不改变沙箱或自动批准越权操作。

开始、受阻和完成时调用 `workflow_status`，在对话里展示其简短文字流程图。完整状态同步到插件自动打开的小窗，不向工具输出写 ANSI 全屏控制序列，也不抢占当前 CLI 的输入界面。关闭小窗不会停止任务；后续阶段上报不会强制重开，下一项新任务才会再次打开。若工具返回 window_error，如实告知窗口未成功打开，继续处理已授权任务。

任务完成后返回结果和证据，继续接受用户追问。插件安装、启用与其他技能选择使用原生 `/plugins`、`/skills`，不模拟或编造自定义斜杠命令。

若工具报告缺少 TypeSafe key，提示用户在该项目的 `配置Jev密钥.cmd` 中隐藏输入，不让用户将密钥发到聊天里。API 错误要如实报告，不能用随机概率替代。
